# tests/: the test suite

These are automated tests for every module. They run offline: Coinbase is replaced by fake clients, files go to temporary folders, and charts render without a window. You need no API key and no network connection.

## Running the tests

From the **repository root**, with the virtual environment active:

```bash
pip install pytest            # once; pytest is not in requirements.txt
python -m pytest              # the whole suite
python -m pytest -q           # quieter output
python -m pytest tests/test_risk.py          # one file
python -m pytest -k flash_crash              # tests whose names match
```

Use `python -m pytest`, not plain `pytest`. The tests import the project modules (`backtest`, `engine` and so on) and shared helpers from `tests.test_backtest` and `tests.test_indicators`. Nothing in the repository (its `tests/conftest.py` included) sets the import path. `python -m` puts the current folder, the repository root, on the import path; plain `pytest` does not, and every file fails at collection with import errors.

`tests/conftest.py` keeps tests away from your real files. Every test's simulator options (`data/simulator_options.json`), stress plan and nightmares (`scenarios/`), stress reports and synthetic store point at the test's own temporary folder. As a backstop, the run fails, naming the files, if it changed any of `data/simulator_options.json`, `data/model_performance.csv`, `data/model_lab/queue.json`, `scenarios/*.json` or a currency's `best_model.json`. (Using the simulator or Model Lab while the tests run can trip it too.)

## What each file covers

| File | Covers |
|---|---|
| `test_backtest.py` | Candle granularities and the 10-year window, paging through the candle API without gaps or duplicates, the incremental cache, and the core backtest: entries, exits, hard stops, drawdown pauses, commission on both fills, the model value recorded for every candle, starting capital (and rejecting invalid values), and the report and trade-table text. It also defines the shared helpers. |
| `test_performance_log.py` | The model performance log: adding new models, leaving the file untouched after an identical run, replacing only the changed model's row while keeping its first-recorded time, updating a row when the profile changes, upgrading an older file with fewer columns, and the status-line summary. Also gathering result shards into the log (and keeping them when the merge fails), simultaneous updates from several threads, and waiting for a held lock or taking over a stale one. |
| `test_parallel_backtest.py` | Parallel runs (`parallel_backtest.py`): worker processes running their maths libraries on one thread, results matching a one-after-another run on worker processes, every model logged through its shard, a failing model reported while the others finish, the single candle writer downloading once per market, light results, and shards kept for a later gather when the merge fails. |
| `test_candle_store.py` | The candle database: importing an old CSV cache; that each windowed indicator's lookback matches what its values depend on; metric keys; storing slow indicators as columns and filling in only new candles; not storing fast or history-dependent ones; later windows; recomputing a column whose stored values no longer match; models sharing indicators, with and without flash-crash buys; and backtests giving the same results with and without the store. Also the read-only store used by parallel workers: it never creates, imports or writes, it holds metric columns back for the writer, an extension that no longer joins the stored range is skipped, and readers aren't blocked by a write under way. |
| `test_rules.py` | The rule language: comparisons and logic, unknown values during warm-up, when a rule becomes ready to evaluate (every indicator and lookback warmed up), cross and history functions, duration periods, division by zero giving an unknown value, and rejecting unsafe formulas. Also compiled models producing entry and exit signals, reporting every problem at once, entry rules being required and exit rules optional, checking indicator sources before a run, legacy-profile translation, and a check that **every template in `config/.example/` is valid**. |
| `test_indicators.py` | Period parsing, and indicator values against reference calculations: SMA, WMA, the EMA family, RSI, ATR, Bollinger, MACD, Stochastic, Williams %R, Donchian, the volume indicators and daily VWAP. Also that the trend and volatility indicators stay in range and warm up, indicators fed from other indicators, reporting source loops and bad references, and every type running on realistic data. |
| `test_friction.py` | The friction model: live and fallback fee rates, the `config` and `disabled` sources, the fee buffer multiplier, the friction screen (liquidity buffer, network fee, tax), lookup failures, per-trade tax reserves paid monthly without loss offsets, and blocked signals. |
| `test_risk.py` | Risk handling: the windowed drawdown stop and old highs leaving its window, entry room above the floor, tax reserve withdrawals counted once, the trailing stop, and flash crashes (limit fills, level validation, a reserve the strategy never trades, crashes held through at their real prices, the drawdown limit waiting for recovery, crashes that never recover, and stops that gap through). |
| `test_start_date.py` | Starting a test later with warmed-up indicators, waiting for a fresh signal, start dates outside the data, parsing start dates, where buy and hold starts (the first candle the model could buy on), and the start-date and buy-and-hold report lines. |
| `test_model_search.py` | The model search (`model_search.py`): library conditions validating on daily candles, recovering reference vote profiles as genomes, built profiles passing validation, persistence snapped to whole candles, mutation and crossover keeping vote thresholds in range, and characteristic lifts favouring the best models. Also models that trade identically counting once, condition similarity, keeping a diverse set, new models taking the next unused names (never one in the discard folder or the log) and skipping profiles already there, simultaneous writers never sharing a name, defaults for older settings files, and `auto` workers sharing the CPUs. |
| `test_synthetic.py` | Synthetic scenarios (`synthetic.py`): synthetic candles kept in their own tables in `data/synthetic/synthetic.db` (only the candles a run made or changed, described in `synthetic_runs`, stored once) and the history store refusing them, each type following its shape and ending where it says, paths that wander like a market (off the straight line, with up days in a bear market and fat tails), chained runs continuing from each module, a chain written into history, consistent candles on the candle grid, seeds and paths, writing a scenario into history at a date (and refusing dates outside it), scenario mistakes, scenario sets, intraday lengths; and in the simulator, the scenario matrix's robustness order, each currency's historically best models, synthetic-only and historic-plus-synthetic runs (only historic results logged), and the editor's chaining, drag-and-drop reordering and duplicating. |
| `test_data_manager.py` | Clearing stored data (`data_manager.py`, `CandleStore.markets`/`clear`, `SyntheticStore.clear`): markets listed with their candles, dates and stored indicators; clearing chosen markets or all of them, with their indicator columns and an earlier version's CSV cache, leaving the others; the synthetic store cleared; and the dialog asking first, refusing while a run is under way, and updating its list. |
| `test_stress_test.py` | Stress tests (`stress_test.py`): at least three severe nightmares, combinations (every run alone plus seeded chained pairs, paths capped), every model run alone and with history, the reports and CSV, worker processes giving the same records in the same order as a single-threaded run, a task per model per scenario path (and per model on history), never two tasks of a model at once and never more workers than models, synthetic scenario runs on workers matching a single-threaded run and naming runs that don't fit the history, workers reporting what they are running, verdicts, the simulator's stress mode logging nothing, the stress plan (the default written once and an edited plan kept, independent of later scenario-set edits, empty combinations refused), and the plan tab building, reordering, duplicating and saving combinations. |
| `test_model_lab.py` | Model Lab (`model_lab.py`): telling search settings from goals files and explaining unusable ones (including a missing template), the saved queue (a running search queued again), the search command a queued job becomes, the runner's order, output and outcomes, its limit on searches at once, Stop ending running searches and leaving the rest queued, and the window: listing files, running a queue with a stand-in search command, the top-20 table, and reordering and clearing the queue. |

| `test_search_registry.py` | The shared registry (`search_registry.py`): context keys, evaluations shared between searches in one context only, the best of other searches first, and many searches recording at once. |
| `test_simulator_run.py` | The simulator's background run: the API is tested before any download, a failed API test stops the run, models share downloads, each model keeps its own capital, model naming and grouping, the comparison table (first buy, B&H start, vs buy and hold), recording each run in the model performance log, running models on parallel workers (a failing model named in the status line), and parsing the worker count. |
| `test_model_view.py` | Choosing which models the charts show, in a real (off-screen) simulator window: search matching, every model charted after a run, charting the rows selected in the comparison table (several open Model value, one opens Chart), gray rows for models not in view, colors kept when others are hidden, double-clicking a hidden model, and the Choose models dialog keeping choices outside its search and refusing an empty choice. Also the Excel-style comparison filters (a column's distinct values in order, checked values and number tests in shown units combining across columns, the heading drop-down marking a filtered column, searching, Select All and refusing an empty choice, values offered after the other columns' filters, sorting from the drop-down, and filtered rows staying hidden through sorting), discarded models listed only with **Include discarded models**, the stress test's Workers table (shown, updated in place, hidden when the run ends), auto giving every model its own worker, the Scenario charts tab (data sets listed by market and scenario with their paths under them, each charted on its own with a mark where the scenario starts, Previous and Next stepping through every path), the Run button passing the chosen data mode (not the timing label) to the run, the two-list model picker (moving models between Available and Selected, keeping the order they were added in, reordering, Add all honouring the currency filter and search, and other ways of selecting filling Selected), the Models list reading currency folders and filtering by currency, each currency's best model being recorded, starred and selected after a full-history run (not after a run from a start date, and not when the box is unticked), and being selected when the simulator opens. It is skipped where Tk has no display. |
| `test_simulator.py` | Loading a profile file, and parsing the chart floor you type in (blank, numbers with `$` and commas, and rejecting text, zero, negatives and infinity). |

## Shared helpers

Two files define helpers that other files import. From `test_backtest.py`:

| Helper | Purpose |
|---|---|
| `_candle(start, close, low=None, high=None, open_=None)` | Builds one candle dictionary. Prices you leave out default to `close`. |
| `_profile(**overrides)` | Builds a small, valid EMA-crossover profile. Keyword arguments replace top-level fields. |
| `FakeCandleClient` | Stands in for the Coinbase client. It serves a flat-priced candle for every minute and records each request it receives. |

From `test_indicators.py`, used by `test_candle_store.py`, `test_rules.py` and `test_chart.py`:

| Helper | Purpose |
|---|---|
| `_candles(count=400, seed=7)` | Builds a deterministic random walk of 15-minute candles with realistic highs, lows and volume. |
| `FIFTEEN_MINUTES` | The candle size those candles use, in seconds (900). |
| `_assert_close(actual, expected)` | Compares two series to within 1e-9, treating matching `NaN` warm-up values as equal. |

## Adding tests

Name new files `test_*.py` and their functions `test_*`. Reuse the helpers above. Keep tests offline by passing fake clients and using pytest's `tmp_path` for files. Never use the real `.env` file or the network.
